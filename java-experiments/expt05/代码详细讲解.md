## People.java：选手抽象类

### 这个文件负责什么

私有属性 name 保存姓名，kind 保存拿手菜。getter/setter 提供访问，构造方法负责初始化，抽象方法 knife 要求子类提供具体烹饪方式。

### 程序怎样执行

创建 ZhangSan 或 LiSi 时，先通过 super 初始化 People 的属性，再执行具体类中的行为。

### 完整源码

```java
// 抽象类保存选手共同的资料，并约定烹饪方式。
public abstract class People {
    private String name;
    private String kind;

    public People() {
        this("未填写", "未填写");
    }

    public People(String name, String kind) {
        this.name = name;
        this.kind = kind;
    }

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public String getKind() { return kind; }
    public void setKind(String kind) { this.kind = kind; }

    public abstract void knife();
}
```

## DoFood.java：做菜接口

### 这个文件负责什么

makeFood 约定展示姓名与菜品的行为。接口只有一个抽象方法，因此可以用 Lambda 提供实现。

### 程序怎样执行

具体选手 implements DoFood 后重写 makeFood；主持人则用 Lambda 实现同一方法。

### 完整源码

```java
// 只有一个抽象方法的接口，可以使用 Lambda 实现。
@FunctionalInterface
public interface DoFood {
    void makeFood(String name, String kind);
}
```

### 逐行解释

| 行号 | 代码 | 解释 |
| --- | --- | --- |
| 1 | `// 只有一个抽象方法的接口，可以使用 Lambda 实现。` | 注释说明：只有一个抽象方法的接口，可以使用 Lambda 实现。。 |
| 2 | `@FunctionalInterface` | 请编译器检查接口只有一个抽象方法，从而能够用 Lambda 实现。 |
| 3 | `public interface DoFood {` | 声明做菜接口，方法默认具有 public abstract 的含义。 |
| 4 | `void makeFood(String name, String kind);` | 声明接口方法，接收姓名和菜品两个字符串，不返回值。 |
| 5 | `}` | 右大括号结束前面的代码块，可在 IDEA 点击括号查看配对。 |

### 容易弄错的地方

接口描述能力，People 保存共同状态。本实验的 makeFood 参数是姓名和菜品，不要与无参的 knife 混淆。

## Test.java：比赛入口与 Lambda 计票

### 这个文件负责什么

创建选手、展示菜品，用 List 保存每张选票，通过 Lambda 遍历、Stream 过滤和 count 计数，最后输出胜负。

### 程序怎样执行

默认5票依次为张三、李四、张三、李四、张三，张三3票、李四2票。参数传入“李四 李四 张三”可得到李四胜；“张三 李四”为平局。

### 完整源码

```java
import java.util.ArrayList;
import java.util.List;

// 比赛入口：展示菜品、保存选票、逐票显示、统计并公布结果。
public class Test {
    public static void main(String[] args) {
        ZhangSan zhangSan = new ZhangSan();
        LiSi liSi = new LiSi("李四", "回锅肉");
        System.out.println("-------比赛开始-------");
        zhangSan.makeFood(zhangSan.getName(), zhangSan.getKind());
        zhangSan.knife();
        liSi.makeFood(liSi.getName(), liSi.getKind());
        liSi.knife();

        // DoFood 是函数式接口，箭头右侧是 makeFood 的实现。
        DoFood host = (name, kind) -> System.out.println(name + "宣布：" + kind);
        host.makeFood("主持人", "比赛结束，评委投票");

        List<String> votes = new ArrayList<>();
        if (args.length == 0) {
            votes.add("张三");
            votes.add("李四");
            votes.add("张三");
            votes.add("李四");
            votes.add("张三");
        } else {
            // 可在 IDEA 的 Program arguments 填入选手姓名，以空格分隔。
            for (String name : args) {
                votes.add(name);
            }
        }

        // 每张票只能属于参加比赛的选手。
        for (String vote : votes) {
            if (!zhangSan.getName().equals(vote) && !liSi.getName().equals(vote)) {
                System.out.println("无效选票：" + vote + "，请使用张三或李四");
                return;
            }
        }

        System.out.println("评委选票：");
        votes.forEach(v -> System.out.println(v));
        long zhangVotes = votes.stream()
                .filter(v -> zhangSan.getName().equals(v))
                .count();
        long liVotes = votes.stream()
                .filter(v -> liSi.getName().equals(v))
                .count();

        System.out.println("张三：" + zhangVotes + "票");
        System.out.println("李四：" + liVotes + "票");
        String result = zhangVotes == liVotes
                ? "平局" : (zhangVotes > liVotes ? "张三胜" : "李四胜");
        System.out.println("比赛结果：" + result);
    }
}
```

## 板书中的集合与本项目的对应关系

List 是接口，ArrayList 和 LinkedList 都是它的实现。List 允许重复并保存顺序，适合一张一张保存选票。Set 会去掉重复值，不能直接用来保存所有原始选票。Map 可以保存姓名与票数的映射，本次按板书重点使用 Stream 分别计票。

Lambda 的基本写法为“参数 -> 表达式”。votes.forEach 使用 Lambda 逐项输出；filter 使用返回 true/false 的 Lambda 选择选票；DoFood host 展示自己定义的函数式接口也可以接收 Lambda。三种场景应分别理解。

与提要相比，比赛入口从接口中移至 Test。胜负通过实际票数决定，并补充平局及无效姓名处理。程序默认使用固定5票；可选的启动参数用于重复测试，没有 Scanner 键盘菜单。

在 IDEA 的 Program arguments 中填入“李四 李四 张三”并运行，可得到李四2票、张三1票。填入“张三 李四”可得到平局。直接运行默认是张三3票、李四2票。运行入口 Test，旧 CookingApp 也能转交启动。

抽象类和接口文件应分别创建在同名 Java 文件中。先读 People、DoFood，再读两个选手类，最后从 Test.main 跟着实际输出理解整个流程。
